# 🍱 Lunch Stamp（お昼ごはんスタンプラリー）

Lunch Stampは、ランチのお店選びに迷う都内オフィスワーカー向けのWebアプリです。  
人形町エリアの飲食店を検索し、訪問したお店を記録することで、日々のランチ開拓をスタンプラリー感覚で楽しめます。

現在はMVPとして、**人形町エリア**に特化して開発しています。

---

## 🌐 アプリURL

https://lunch-stamp.onrender.com

---

## 📝 アプリ概要

Lunch Stampは、日々のランチ選びを「スタンプラリー」として楽しめるWebアプリです。

Hotpepper APIを利用して飲食店情報を取得し、ユーザーは気になった店舗の詳細を確認できます。  
訪問した店舗は「訪問済み」として記録でき、マイページでは訪問数や達成率を確認できます。

単なる店舗検索ではなく、訪問記録を残すことで、ランチ開拓を継続しやすくすることを目的としています。

## 💡 作成背景

社会人になってから、毎日のランチで同じお店ばかりに行ってしまうことに気付きました。

職場周辺には多くの飲食店があるにもかかわらず、  
「どこに行くか考えるのが面倒」  
「前に行ったお店を覚えていない」  
「新しいお店に行くきっかけがない」  
という課題を感じていました。

そこで、ランチ店探しを単なる検索ではなく、訪問記録や達成率を通して楽しめる仕組みにすることで、日常のランチを少し楽しくできると考え、このアプリを作成しました。

## ✅ 主な機能

### 認証機能

- ユーザー登録
- ログイン / ログアウト
- Remember me によるログイン状態保持
- アカウント有効化メール
- パスワード再設定メール
- プロフィール編集

### 店舗検索・詳細機能

- Hotpepper APIを利用した店舗検索
- キーワード検索
- ジャンル検索
- 予算検索
- 店舗詳細表示
- 店舗画像・住所・ジャンル・予算・外部URL表示

### 訪問記録機能

- 店舗を「訪問済み」として記録
- 訪問済み解除
- 1ユーザー × 1店舗につき1記録のみ
- マイページで訪問済み店舗を一覧表示

### マイページ

- ユーザー情報表示
- 訪問済み店舗数
- 達成率表示
- 最近の訪問履歴表示

### 管理者機能

- 管理者専用ユーザー一覧画面
- `/admin/users` への直打ちアクセスのみ
- 一般ユーザーはアクセス不可
- `admin` フラグはフォームから変更不可
- 管理者権限はアプリ画面から付与できない設計

### 監査ログ機能

以下の重要操作を監査ログとして記録します。

- ログイン
- ログアウト
- 訪問済み登録
- 訪問済み解除

記録内容：

- ユーザーID
- 操作種別
- 操作対象
- IPアドレス
- User-Agent
- 実行日時

また、管理者のみ監査ログ一覧の閲覧とCSVダウンロードが可能です。

## 🔐 セキュリティ面で意識したこと

SIEM製品の営業経験から、認証・認可・ログ管理を特に意識して実装しました。

### 認証・パスワード管理

- `has_secure_password` と BCrypt によるパスワードハッシュ化
- パスワードを平文保存しない設計
- アカウント有効化メールによる本人確認
- パスワード再設定トークンの有効期限管理

### セッション管理

- ログイン時に `reset_session` を実行（セッション固定攻撃対策）
- Remember me トークンはDBに平文保存せず、digest化して保存
- ログアウト時にセッションとRemember me情報を適切に削除

### 認可

- ログイン必須ページでは `logged_in_user` によるアクセス制御
- ユーザー編集では本人のみ操作可能
- 他人のデータ編集を防止
- 管理者専用画面では `admin_user` による権限チェック
- URL直打ちでも一般ユーザーは管理者画面にアクセス不可

### Mass Assignment対策

- Strong Parametersで許可する属性を限定
- `admin` カラムは `permit` に含めない設計
- 一般ユーザーがリクエストパラメータ改ざんで管理者権限を取得できないように制御

### 秘密情報管理

- Hotpepper APIキーはRails credentialsで管理
- SendGrid APIキーは環境変数で管理
- `master.key` や `.env` はGit管理対象外
- `.gitignore` で秘密情報を確実に除外
- 本番環境では `config.require_master_key = true` を有効化し、キー未設定による予期せぬ挙動を防止

### 通信・本番環境設定

- `config.force_ssl = true` によるHTTPS通信の強制
- 本番DBはPostgreSQLを使用
- SQLite本番運用を廃止し、永続的なデータ管理を実現

### 監査ログの堅牢化

- 重要操作の追跡性を担保
- ログにはパスワードや各種トークンなどの機密情報を含めない設計
- 監査ログの閲覧およびCSV出力機能は、Controllerレベルで管理者のみに厳格に認可
- CSV Injection対策として、危険な先頭文字をサニタイズ

### CSP（Content Security Policy）

- アプリの動作に必要な外部リソースを許可しつつ、CSPを設定
- `object-src 'none'`
- `frame-ancestors 'none'`
- `form-action 'self'`
- Bootstrap CDNなど信頼できる外部リソースのみ最小限許可

## 🏗️ 本番環境構成

本番環境はRenderにデプロイしています。

- Webアプリケーション：Render Web Service
- データベース：Render PostgreSQL
- メール送信：SendGrid Web API
- 店舗情報取得：Hotpepper API

当初は本番環境でもSQLiteを使用していましたが、Renderのデプロイ時にSQLiteのDBファイルが永続化されず、ユーザー情報や訪問履歴が消える問題が発生しました。

そのため、本番DBをPostgreSQLへ移行し、以下のデータがデプロイ後も保持されるようにしました。

- ユーザー情報
- アカウント有効化状態
- 訪問履歴
- 監査ログ
- 管理者権限
